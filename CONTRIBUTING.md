# Contributing to goedels-poetry-lib

This repository is an autonomous, append-only proof corpus. All theorem files are generated by LLM-based provers and merged automatically.

## How Theorems Are Added

Theorems are not added manually. Instead, they are generated by an external system ([goedels-poetry](https://github.com/KellyJDavis/goedels-poetry)) which:
1. Generates theorem proofs using LLM-based provers
2. Creates automated PRs with new theorem files
3. Each PR contains exactly one new `.lean` file with one theorem

## File Structure and Naming

### Directory Structure

Theorems are organized by category:
- `GoedelsPoetryLib/Logic/` - Logic-related theorems
- Additional categories will be added as the corpus grows

### File Naming

- **Standard naming**: `<theorem name>.lean`
- **Conflict resolution**: If a theorem name already exists in the same directory, append a monotonically increasing number:
  - First conflict: `<theorem name>1.lean`
  - Second conflict: `<theorem name>2.lean`
  - And so on...

### Example

If a theorem named `Commutativity` is added to `Logic/`:
- First instance: `GoedelsPoetryLib/Logic/Commutativity.lean`
- Second instance: `GoedelsPoetryLib/Logic/Commutativity1.lean`
- Third instance: `GoedelsPoetryLib/Logic/Commutativity2.lean`

## Append-Only Policy

This repository enforces a strict append-only policy:

- **No modifications**: Once a theorem file is merged, it cannot be modified
- **No deletions**: Theorem files cannot be deleted (enforced by external controls and CI checks)
- **No overwrites**: New files cannot overwrite existing files (detected by CI)

The `check_append_only.sh` script validates these rules in CI.

## Init.lean Files

### Subdirectory Init.lean Files

Subdirectory `Init.lean` files (e.g., `GoedelsPoetryLib/Logic/Init.lean`) are **auto-generated** by `scripts/regenerate_init.py`. These files:
- Should never be edited manually
- Are regenerated automatically during PR validation in CI (before merge)
- Import all `.lean` files in their directory (except other `Init.lean` files)
- Import subdirectory `Init.lean` files for nested directories

### Root Init.lean File

The root `GoedelsPoetryLib/Init.lean` file is **manually maintained**. It:
- Is not regenerated by `regenerate_init.py` (which only processes subdirectories)
- Imports subdirectory `Init.lean` files (e.g., `import GoedelsPoetryLib.Logic.Init`)
- Must be updated manually when new top-level categories are added

**Note**: Since no new top-level files will be added to `GoedelsPoetryLib/`, the root `Init.lean` only needs updates when new subdirectories are created.

## CI Process

When a PR is created, the following security and validation checks are performed:

1. **Branch name validation**: Branch name must start with `add-theorem-` when adding theorem files
   - Only enforced when PRs add new theorem files (`.lean` files excluding `Init.lean`)
   - Maintenance/workflow changes can use any branch name
   - Prevents arbitrary branch names for theorem additions
   - Ensures branches follow expected naming convention for automated PRs

2. **File path validation**: Only `.lean` files in `GoedelsPoetryLib/<category>/.../<filename>.lean` pattern are allowed (when adding theorem files)
   - Only enforced when PRs add new theorem files (`.lean` files excluding `Init.lean`)
   - Maintenance/workflow changes can modify any files
   - Supports nested subdirectories: `GoedelsPoetryLib/Logic/SetTheory/Commutativity.lean`
   - Prevents files in unauthorized locations in theorem PRs
   - Blocks non-.lean files from being added in theorem PRs

3. **Critical file protection**: Modifications to protected files/directories are blocked (when adding theorem files)
   - Only enforced when PRs add new theorem files
   - Maintenance/workflow changes can modify protected files
   - Protected files/directories:
     - `scripts/` - Scripts directory
     - `.github/` - CI configuration
     - `lakefile.lean`, `lean-toolchain`, `.gitignore` - Build configuration
     - `README.md`, `CONTRIBUTING.md`, `LICENSE` - Documentation
     - `GoedelsPoetryLib/Init.lean` - Root Init.lean (manually maintained)

4. **One file per PR validation**: Each PR must add exactly one new theorem file (when adding theorem files)
   - Only enforced when PRs add new theorem files
   - Maintenance/workflow changes can modify multiple files
   - Prevents batch additions that could bypass validation
   - Ensures focused, reviewable changes for theorem additions

5. **Build**: `lake build` compiles the main library
   - Validates that the new theorem file has correct Lean syntax
   - Catches compilation errors early

6. **Test**: `lake build Tests` compiles the test suite
   - Ensures the new theorem doesn't break existing tests
   - Verifies the import chain is intact

7. **Append-only check**: `check_append_only.sh` validates:
   - No theorem files were modified
   - No theorem files were deleted
   - No new files overwrite existing files
   - Requires `origin/main` to be fetched (handled automatically by CI; CLI contributors fetch programmatically)

8. **Init regeneration**: `regenerate_init.py` updates subdirectory `Init.lean` files

9. **Init commit**: Generated `Init.lean` files are committed and pushed to the PR branch
   - **Critical**: If the push fails, the PR will fail validation
   - This ensures the repository never enters an invalid state (theorem added without corresponding `Init.lean` update)
   - Since PRs come from branches (not forks) created by the CLI, write permissions are available

10. **Validation**: `lake build` and `lake build Tests` are run again to validate that the regenerated `Init.lean` files compile correctly
    - This ensures the generated `Init.lean` files are syntactically correct and all imports are valid
    - If validation fails, the PR will not merge

11. **Clean check**: Verifies no unexpected changes were made (excluding `Init.lean` files)

If all checks pass and the PR is from a bot, it is automatically merged.

**Note on Init.lean staleness**: If `Init.lean` regeneration or commit fails, the PR will not merge. This is intentional - it prevents the repository from entering an invalid state where a theorem exists but isn't imported. The external CLI system should retry the PR after addressing any push permission issues.

## Testing

### Test Structure

The `Tests/` directory contains test files that verify the library can be imported correctly.

#### Current Structure (Import Aggregator)

Currently, `Tests/FullImport.lean` imports the entire library:
```lean
import GoedelsPoetryLib
```

This verifies that all modules can be successfully imported and compiled.

**How it catches breakage**: The import chain works as follows:
1. `import GoedelsPoetryLib` imports `GoedelsPoetryLib.Init`
2. `GoedelsPoetryLib.Init` imports `GoedelsPoetryLib.Logic.Init` (and other subdirectory Init files)
3. `GoedelsPoetryLib.Logic.Init` (auto-generated) imports all `.lean` files in `Logic/`
4. For nested directories, `Logic/SubDir/Init.lean` imports all files in `SubDir/`

Since `regenerate_init.py` maintains this import chain automatically, `FullImport.lean` will catch:
- **Syntax errors** in any theorem file (caught during compilation)
- **Missing imports** in theorem files (caught when the file is imported)
- **Broken Init.lean chain** (caught if a subdirectory Init.lean is missing or broken)
- **Type errors** in theorem statements (caught during compilation)

**Potential edge cases not caught**:
- Runtime errors that only manifest when theorems are actually used (not just imported)
- Subtle dependency issues that only appear in specific import orderings
- Issues in files that aren't properly connected to the Init.lean chain (shouldn't happen with auto-generation)

For an append-only proof corpus where theorems are validated before PR creation, `FullImport.lean` provides sufficient coverage.

#### Alternative Structure (Per-Test Files)

If individual theorem tests are needed in the future, tests could be structured as:
```
Tests/
  FullImport.lean          # Import all (current)
  Logic/
    CommutativityTest.lean # Test specific theorem
    AssociativityTest.lean # Test specific theorem
```

Each test file would:
- Import the specific theorem being tested
- Contain test cases or verification code
- Be compiled as part of `lake build Tests`

## Scripts

### `check_append_only.sh`

Validates the append-only policy:
- Checks for deleted files
- Checks for modified files
- Checks for files that would overwrite existing files

**Usage**: Run automatically in CI, or manually:
```bash
bash scripts/check_append_only.sh
```

### `regenerate_init.py`

Regenerates subdirectory `Init.lean` files based on current directory contents.

**Usage**: Run automatically in CI during PR validation, or manually:
```bash
python3 scripts/regenerate_init.py
```

**Scope**: Only processes subdirectories within `GoedelsPoetryLib/`, not the root level.

**Important**: This script runs during PR validation (not post-merge) so that:
- Generated `Init.lean` files are part of the PR being validated
- The build can verify the generated files compile correctly
- If the commit/push fails, the PR fails (preventing invalid repository state)

## External Systems

This repository is designed to work with external proof generation systems:
- Proof generation: [goedels-poetry](https://github.com/KellyJDavis/goedels-poetry)
- PR creation: Automated by the external system
- Deletion prevention: Handled by external controls (in addition to CI checks)

## GitHub Branch Protection Requirements

To ensure the automatic merge workflow functions safely, the following branch protection rules must be configured for the `main` branch:

### Required Settings

1. **Require a pull request before merging**
   - ✅ Enabled
   - Required number of approvals: 0 (since PRs are from bots)

2. **Require status checks to pass before merging**
   - ✅ Enabled
   - **Required status check**: `build` (the CI job name)
   - **Require branches to be up to date before merging**: ✅ Enabled (recommended)

3. **Require conversation resolution before merging**
   - ⚠️ Optional (can be disabled for bot PRs)

4. **Do not allow bypassing the above settings**
   - ✅ Enabled (prevents force pushes that could bypass CI)

### Why These Settings Matter

- **Status check requirement**: Ensures the `build` job (which includes all validation steps) must pass before auto-merge can proceed
- **Up-to-date requirement**: Ensures PRs are rebased/updated with latest `main` before merging
- **No bypass**: Prevents accidental merges that skip CI validation

### Configuration Path

GitHub Settings → Branches → Branch protection rules → Add rule for `main` branch
